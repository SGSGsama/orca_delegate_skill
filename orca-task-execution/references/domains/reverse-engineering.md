# Reverse-Engineering Domain

Load for a delegated `reverse` Task. It defines evidence ownership and synthesis; load only the selected Terra or Luna contract for worker behavior.

## Coordinator ownership

The primary coordinator owns the global target model, accepted vocabulary, algorithm/behavior reconstruction, evidence standard, competing global hypotheses, complex protection or anti-analysis reasoning, mutation policy, contradictions that change the global model, and final synthesis.

Build context in layers:

```text
Global model: objective, artifact identities/digests, subsystem map,
accepted behavior/vocabulary, hypotheses, mutation policy, context version

Evidence index: input coverage, stable identifiers, facts/clusters/anomalies,
raw-source references, skipped items, schema and reproduction command

Local target packet: exact functions/addresses/ranges, one semantic question,
relevant global facts, bounded evidence slice, mutation scope and acceptance
```

## Domain routing

- Terra: one function or tightly coupled cluster, local data/control flow, structure fields, state transitions, precise hypothesis tests, or difficult IL interpretation.
- Luna: logs, traces, dumps, exports, candidate sets, corpus/version comparison, repetitive classification, coverage accounting, normalization, or accepted annotation propagation.
- Primary coordinator: global algorithms, system behavior, complex protection, cross-target contradictions, evidence/mutation policy, and final validation.

Use the evidence pipeline only when useful: Luna turns bulk inputs into indexed evidence, Terra resolves bounded local semantics, and the coordinator performs global synthesis. Do not make Terra read whole corpora or Luna invent semantic meaning.

## Acceptance

Luna output must account for processed/skipped/error coverage and link every result to raw evidence. Terra output must identify actual targets/evidence slices, distinguish plausible hypotheses, cite decisive evidence, record confidence and residual ambiguity, and remain inside mutation scope.

Persistent analysis mutations require explicit scope, artifact identity/revision, isolation when needed, and reload/query/export validation. A worktree does not isolate an external analysis database or GUI session.
